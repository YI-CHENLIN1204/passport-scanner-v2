# OCR Requirements

## 原則：只辨識有價值的資料

V2 不追求「把證件上所有文字都 OCR 出來」。欄位越多，不代表產品越好；無業務價值欄位會增加辨識錯誤、人工核對負擔、資料庫複雜度與敏感資料保存量。

因此每種證件只擷取旅行社作業、旅客識別、證件有效性或未來有合理 CRM 分析價值的欄位。

## 護照

最低需求方向：

- 英文姓名。
- 護照號碼。
- 國籍。
- 簽發國 / issuing state。
- 出生日期。
- 性別（若業務流程需要）。
- 護照有效期限。
- 簽發日期（若後續流程確有需要）。
- 出生地：可保留為候選欄位，因可能具 CRM / 客群分析價值，但需先確認實際分析用途。
- MRZ 原始值或解析結果：可用於交叉驗證，但是否長期保存需另行決定。

注意：即使主要客群是台灣旅客，也不能把 nationality 或 issuing country 固定寫死為 TWN。

## 台灣身分證

正式第一版欄位：

- 中文姓名。
- 國民身分證統一編號。
- 出生日期。
- 性別。

辨識與驗證：

- 使用 PP-OCRv5 瀏覽器端 OCR。
- 與護照、台胞證共用 0° / ±90° / 180° 自動方向校正與必要的小角度 deskew。
- 身分證字號只接受 1 碼英文 + 9 碼數字，且第 2 碼必須為 1 或 2。
- 前後端都重新計算國民身分證統一編號檢查碼，不信任 OCR metadata。
- 性別由身分證字號第 2 碼交叉驗證：1 → M、2 → F；若字號尚未可靠取得，性別不得預設。
- 出生日期支援民國年文字格式轉換為 YYYY-MM-DD，也支援 OCR 直接讀到西元日期。
- 中文姓名優先依「姓名」標籤與附近文字定位；抓不到時允許人工補填。
- 全欄人工覆核後才允許儲存。

不保存發證日期、發證地點、領補換類別等目前沒有旅行作業／CRM 必要性的欄位。

## 台胞證

方向以實際旅行作業需要為準，優先：

- 姓名。
- 台胞證號碼。
- 出生日期。
- 有效期限。
- 與旅客本人識別／證件有效性直接相關的必要欄位。

## 明確不優先蒐集

除非未來出現清楚的業務需求，V2 不為了「完整」而特別訓練或保存：

- 發照機關。
- 發照地。
- 發證類別。
- 換證次數。
- 曾持證加註。
- 其他對旅行社作業、CRM 或證件驗證沒有明確價值的欄位。

## 人工覆核

每份證件都必須有人工覆核畫面：

- 左側／上方可看到原始證件。
- 右側／下方顯示結構化欄位。
- 欄位可人工修正。
- 低信心或格式驗證失敗欄位要醒目標記。
- 人工確認後才可視為可用資料。

## 訓練 / 微調資料

若未來實測發現 OCR 準確率不足，可能需要累積更多已人工校正的影像／標註資料做訓練或微調。

這會直接影響證件照片保存期限，因此不能由開發者自行把保存期限改成永久；必須先完成隱私、用途與保存政策決策。


## 護照人工覆核 V1

PaddleOCR 護照流程通過第一輪 5 / 5 泛化測試後，正式覆核卡第一版只呈現目前已確認有業務價值且可由 MRZ 取得的欄位：

- 英文姓名。
- 護照號碼。
- 國籍。
- 簽發國。
- 出生日期。
- 性別。
- 有效期限。

覆核規則：

- 原始護照圖片與欄位同畫面顯示。
- 所有欄位都可人工修改。
- 護照號碼、出生日期、有效期限若 MRZ check digit 通過，顯示「檢查碼通過」。
- 英文姓名即使 TD3 Line 1 結構完整，仍顯示「人工確認」。
- 國籍、簽發國、性別屬 MRZ 結構欄位，不因 Line 2 check digit 通過就宣稱為獨立驗證成功。
- OCR / 驗證層仍保留 MRZ 的 YYMMDD 原值；人工覆核 UI 轉為 YYYY-MM-DD，方便使用者閱讀與修改。
- 出生日期世紀推定採「推定為不晚於目前年份的最近世紀」；有效期限則以接近目前使用期的世紀為優先。兩者都必須可人工修改，最終以人工覆核結果為準。
- 第一版「確認資料」只代表瀏覽器端人工覆核完成，尚未寫入 traveler_master、document_versions、後端 API 或 Google Sheets。


## 覆核畫面後續 UX 強化

人工覆核卡目前採「左側原始證件、右側可編輯欄位」。

已完成：

- 原始證件圖片可用滑鼠滾輪或按鈕縮放，範圍 100%～400%。
- 放大後可直接拖曳／平移。
- 可一鍵回到適合視窗；雙擊圖片也會重設。
- 使用 Pointer Events，滑鼠與觸控操作共用同一套行為。
- 只改變覆核畫面的檢視狀態，不修改、重壓縮或重新上傳原始圖片本身。


## 台灣護照 VIZ 中文姓名

護照 MRZ 不含中文姓名。為支援 CRM 主檔，台灣護照需額外從 VIZ（Visual Inspection Zone）取得中文姓名。

第一版流程：

1. PP-OCRv5 完成整頁辨識。
2. MRZ parser 處理英文姓名與可驗證欄位。
3. VIZ parser 從中文字串中排除護照固定標籤，優先選擇靠近「姓名」標籤的個人姓名候選。
4. 若整頁沒有可靠中文姓名，再裁切台灣護照 VIZ 區域重試。
5. 仍抓不到就留空，由人工輸入。
6. 中文姓名一定要人工對照原圖勾選確認，才允許保存。

不做：

- 不由英文姓名自動翻譯／音譯中文姓名。
- 不把「中華民國、護照、外交部、出生日期、簽發機關」等頁面文字當姓名。
- 不因 OCR 高 confidence 就跳過人工確認。


## 台胞證第一版正式流程

台胞證為第二種正式 OCR 證件；後續身分證亦沿用同一套自動方向校正與人工覆核框架。

第一版只保留旅行社／CRM 直接需要的欄位：

- 中文姓名。
- 台胞證號碼。
- 出生日期。
- 性別。
- 有效期限。

不保存：

- 簽發次數。
- 簽發機關。
- 曾持證加註。
- 其他目前沒有旅行作業／CRM價值的欄位。

辨識規則：

- 使用與護照相同的 PP-OCRv5 瀏覽器 OCR instance，不再載入第二套引擎。
- 中文姓名優先依「姓名 / Name」標籤附近文字。
- 台胞證號碼只接受 8 位數字；若 OCR 將正面 8 位證號與後方 2 位簽發次數黏成 10 位，僅取前 8 位證號。
- 出生日期與有效期限統一轉成 YYYY-MM-DD。
- 有效期限若是一段日期區間，取較晚的結束日期。
- 2015 版電子台胞證背面具有 3 × 30 機讀碼；主流程改為優先辨識背面機讀碼並驗證證號、出生日期、有效期限與整體檢查碼。
- 背面機讀碼不可用或只收到正面照片時，才退回正面 VIZ OCR。
- 機讀碼中的中文姓名編碼可作為中文姓名來源；仍保留人工覆核，避免 OCR 對機讀碼字元造成誤讀。
- OCR 抓不到的欄位允許人工補填，不因單一欄位失敗而中止整張證件流程。


## 證件方向校正

護照、台胞證與台灣身分證都必須支援客戶上傳非正向照片：

- 先嘗試原方向。
- 結構不足時自動比較 90°、-90°、必要時 180°。
- 選出 MRZ / 欄位結構最完整的方向。
- 若仍存在約 2.5°～20° 的小角度傾斜，必要時再 deskew。
- 人工覆核畫面顯示校正後版本，但不修改原始上傳檔。
